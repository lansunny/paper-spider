# 关联阅读与社区追问

从精读中的一篇论文出发，四维图提供不同阅读方向，系统提出具体的比较问题，再从正文和 claims 来源锚点收集原文，生成带引用的对照阅读建议。

## 使用

论文精读右侧打开「关联阅读」，填写学习目标后开始。可在「展开阅读建议」中查看完整页面，也可选择「仅整理原文」，关闭追问和解释的模型生成。点击引用展开原文，并进入对应 PDF 页面。

终端预览图邻居，不调用模型：

```bash
python scripts/related_reading.py 2024.eacl-demo.16
```

实际取证与生成：

```bash
python scripts/related_reading.py 2024.eacl-demo.16 --run
python scripts/related_reading.py 2024.eacl-demo.16 --run --evidence-only
```

结果与进度保存在 `runtime/related_reading/jobs/`。模型步骤复用本地缓存，来源版本变更后要求重新生成。

## 图如何参与

从当前论文的真实四维边选取邻居，以连接强度、学习目标相关度和新增阅读方向形成最多 12 篇候选，再由追问规划按学习目标选出最多 5 篇。材料不足时允许少选；没有合适候选时返回空推荐，任务正常结束，不继续正文检索、claims 编码或解释生成。方法或主题社区缺失时，不把两个空社区当成“不同路线”。候选方向包括：

- 主题相近、方法社区不同：同一类问题的其他做法。
- 方法相近、主题社区不同：类似方法的其他应用。
- 实验或结论相近：值得核查的设置、发现和局限。

社区卡片与四维描述引导 2～4 个追问。卡片尚未为当前图生成时，使用同一图的社区成员与论文描述作为导航，不使用旧图卡片。问题必须覆盖所有候选，不允许模型额外添加论文。

## 取证与成本

每个追问都运行完整正文库的 BM25＋Dense，关闭单篇自动路由。B 分支另在当前论文与比较论文中筛选 claims，沿锚点读取原文；社区不硬限制全文范围。

原文候选按文档、页和字符范围去重，为比较的论文分配候选名额，填充开放候选后统一重排。每个追问最多 40 个评分对，总计最多 4 个追问。各路结果融合后，优先为每篇比较论文保留原文，再按 16,000 个序列化证据字符装入上下文。这个字符上限不是 token 上限。

默认生成模型使用提供方可用的 `deepseek-flash` ID，不改应用的全局 `.env`。有候选和原文时，正常在线过程包括追问规划、阅读建议生成、原文核对三个步骤。前两个步骤可能修复重试；原文核对最多一次响应，失败时收起未经核对的对照说明，不反复付费尝试。无合适候选通常只需规划步骤；已缓存步骤不产生新调用。claims 的本地 BGE-M3 编码缓存独立于正文 Qdrant 索引，第一次需要准备，后续复用。

每条推荐理由和差异必须同时引用当前论文和目标论文，阅读位置只能引用目标论文。生成后逐条核对整句事实，重点区分本文与对照组、人工标注所处阶段，以及结果概述与方法细节。核对返回的引句必须实际存在于所引证据中，并还原到 PDF 页和字符坐标。

短说明不复述实验数值、样本数和提升比例，数值与对照设置保留在可展开的原文中；数字相同不足以证明主体和阶段相同。模型版本名可以保留。未通过完整支持检查的说明会收起；缺少推荐理由时降为阅读线索。需要流程、机制、定义等细节的入口，在没有章节定位依据时保守显示为原文片段；不把结果页或概述当作方法流程。点击引用可以看到标出的原文引句。历史结果不改写，尚未核对的旧说明不继续作为已支持的对照展示。

`supported` 表示通过来源约束和模型核对，不代表独立人工确认。引句与坐标可以机械校验，主体归属和语义支持仍可能误判。修复后的功能回归不替代质量评测，也尚未验证用户学习收益。

## 扩展到 200 篇

```bash
python scripts/build_paper_graph.py --config configs/paper_graph_200.json --model deepseek-flash --reuse-current
python scripts/build_paper_graph.py --config configs/paper_graph_200.json --model deepseek-flash --reuse-current --run
```

首条仅预览。第二条校验并保留已发布的兼容描述及原模型来源，新增论文由 Flash 抽取；四维向量和社区重新构建。新图完整成功后才切换 `CURRENT.json`，旧图与个人标注均保留。新图发布后需在研究综述页重新整理社区卡片。
