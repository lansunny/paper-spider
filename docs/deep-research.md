# 深入研究

在问答页选择「深入研究」并直接输入问题。适用于单篇问答、跨论文比较和开放查询。可以勾选已进入 Docling 正文索引的论文，将两轮检索都限定在所选范围内。API 使用 `POST /api/ask` 和 `qa_mode: "deep_research"`。该模式需要配置回答模型和完整发布的 Docling 正文索引。有多个全量 Docling 配置时，通过启动进程的 `PAPERRAG_DOCLING_PROFILE` 指定使用的配置。

1. **首轮取证。** 从 Docling 正文索引检索，中文查询默认翻译成英文。自动路由按显式提到的论文确定范围，明确比较时为各篇论文保留候选，开放查询可以查全库。启用重排时最多处理 100 个正文块，按 16,000 字符预算装入证据。每段原文有稳定的 `S` 编号，并保留 PDF 页码、段落 ID 和字符范围。Agent 同时收到少量论文提示，来自问题中的名称或别名及首轮命中的论文。
2. **判断缺口与补查范围。** Agent 根据原文拆解问题并判断证据是否足够。它可以直接结束检索，或提出最多三项补查：目标明确时限定一篇或几篇论文；需要发现新论文时改写查询，继续检索可用范围。服务校验 JSON、引用、论文 ID、重复查询和手动范围，再独立执行每条补查。补查只运行一轮。
3. **合并证据。** 两轮使用同一索引快照。确实有新段落时，为每条补查最多保留一段，优先保留评估已引用的原文和首轮高排位段落，再按预算回填。没有新段落可用时保留首轮上下文。相同或被原文坐标包含的候选不重复加入，保留的首轮段落沿用原编号。字符数不等于模型 token。
4. **形成回答。** Agent 重新读合并后的原文，输出每个比较项的发现、原文摘录和 `missing_modules`。模型选择同篇论文的摘录编号；摘录是代码从原文预先切出的片段。服务核对编号和论文归属，从原文回填所选摘录，并附上可打开 PDF 页码的引用。一个比较项可以同时有部分发现和未确认部分。结构或引用校验失败时最多纠正一次；仍失败则保留已检索的原文并显示未确认项。摘录可核对，不代表系统已经自动证明结论被原文支持。

Agent 的提示包含停查、定向补查、全库补查和证据不全的完整 JSON 示例。只有含义唯一的缺省字段才会自动补空数组：停查的 `searches`、全库查询的 `paper_ids`、缺证据项的 `citations`。评估阶段会删除未知编号和跨论文误引，将对应模块降为「部分支持」或「缺证据」，保留其他合法模块和查询。服务不因此追加查询或放宽范围。生成时提供按论文分组的摘录编号；如果某条结论引用不存在或归属错误，整条结论撤下，该模块列为未确认，其他有效结论保留。漏答的模块同样列为未确认。追踪记录这些修复，便于区分模型原始输出与最终结果。

请求追踪记录补查目标、查询、证据来源、模型校验状态、耗时与 token。本阶段的真实模型调用用于验证流程。要测量收益，可比较普通问答、固定两轮、证据驱动两轮；后两组匹配最大检索次数、重排输入与上下文预算，检查必要证据齐全率、结论是否受引用支持、补查命中和新增成本。评测标签仅用于计分。

历史 V2 实验可运行 `python scripts/evaluate_deep_research.py --retrieval-only`。该脚本沿用旧索引的证据坐标，对比 V2 普通问答、深入研究首轮和补查后的上下文。Docling 的正文证据使用独立段落坐标，正文基线可用 `python scripts/evaluate_docling_text50.py` 复测。
